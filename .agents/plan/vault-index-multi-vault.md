# Несколько vault и локальный индекс

Статус: поведение подтверждено. Этот документ фиксирует контракт для реализации и проверки.
Документ не подтверждает проверку runtime.

## Цель

Пользователь открывает текущий проект как vault без дополнительных параметров. Один процесс LiveNote
работает с несколькими vault. Заметки остаются в файловой системе и Git. SQLite хранит только локальный
кэш индекса.

## Выбор корня при запуске

Без параметров хранения LiveNote выбирает текущий рабочий каталог:

```bash
cd ~/work/whbrain
livenote
```

Параметр `--vault <путь>` и переменная `LIVENOTE_VAULT` задают корень явно. Параметр `--db <путь>`
сохраняет прежний режим SQLite. Команды `livenote migrate` сохраняют прежнее поведение миграции.

Процесс закрепляет корень из параметров запуска до завершения. Смена рабочего каталога и открытие
другого vault через UI не меняют этот корень.

## Файлы и Git

Обычные файлы заметок и схем остаются в Git. LiveNote не применяет правила `.gitignore` при показе
заметок. Сканирование исключает служебные каталоги `.git` и `.livenote`.

LiveNote не создаёт коммиты и не меняет корневой `.gitignore`. Пользователь управляет Git отдельно.

## Локальный кэш индекса

Файлы vault остаются источником истины. LiveNote хранит кэш индекса по адресу:

```text
~/.livenote/<uuid канонического корня>/index.sqlite
```

UUID соответствует каноническому корню vault. Другой путь получает другой кэш. Новый клон также получает
новый кэш. Пользователь может удалить `index.sqlite` без потери заметок. LiveNote восстанавливает кэш
из файлов vault.

При повторном чтении LiveNote получает метаданные из кэша. Он не анализирует повторно неизменённые файлы.
После редактирования файлов или переключения ветки Git LiveNote обновляет индекс.

## Открытие vault через UI

Пункт «Открыть папку» находится в меню с тремя полосами справа вверху. В macOS этот пункт открывает
системный диалог выбора папки. LiveNote открывает выбранный vault в новой вкладке браузера.
Вкладка использует выбранный vault и не меняет корень из параметров запуска.

Vault, открытый через UI, доступен, пока его использует хотя бы одна вкладка браузера. После ухода
последней вкладки начинается ожидание переподключения. Переподключение в этот период сохраняет vault
открытым. После ожидания LiveNote закрывает vault. Длительность ожидания этот контракт не задаёт.

## MCP

Все агенты подключаются к одному endpoint `/mcp`. Инструмент `list_vaults()` возвращает открытые vault:

```json
{
  "vaults": [
    {
      "id": "<id>",
      "name": "<name>"
    }
  ]
}
```

Инструменты работы с хранилищем принимают необязательный `vault_id`. При одном открытом vault агент может
не передавать `vault_id`. При нескольких открытых vault агент обязан передать `vault_id`.

Если `vault_id` отсутствует при нескольких vault, инструмент возвращает явную ошибку. Если указанный vault
не существует или закрыт, инструмент также возвращает явную ошибку. Инструмент не выбирает другой vault
вместо ошибки.

## HTTP и SSE

Существующие адреса `/api` и `/events` сохраняют совместимость. Без идентификатора vault они используют
корень из параметров запуска.

Адреса с идентификатором выбирают отдельный vault:

```text
/api/vaults/:id/…
/events?vault_id=…
```

Операции одного vault не меняют содержимое другого vault. События SSE содержат обновления выбранного vault.

## Критерии приёмки

1. Запуск из `~/work/whbrain` без параметров хранения открывает этот каталог как vault.
2. `--vault` и `LIVENOTE_VAULT` выбирают явный корень. `--db` и команды миграции продолжают работать.
3. Системный диалог macOS открывает второй vault в новой вкладке браузера. Корень запуска остаётся доступен.
4. Второй vault остаётся открытым во время ожидания переподключения. После ожидания без вкладок он закрывается.
5. `list_vaults()` возвращает объект `vaults` с массивом записей `{id,name}`.
6. При одном vault инструменты работают без `vault_id`. При нескольких vault они требуют `vault_id`.
7. Инструмент возвращает ошибку `vault_not_found` для неизвестного или закрытого `vault_id`.
8. Старые `/api` и `/events` используют корень запуска. Адреса с `:id` и `vault_id` выбирают указанный vault.
9. Правила `.gitignore` не скрывают заметки. Каталоги `.git` и `.livenote` не попадают в список заметок.
10. Другой путь и новый клон используют отдельные файлы `index.sqlite`. Удаление кэша не удаляет заметки.
11. Повторное чтение не анализирует неизменённые файлы. Внешнее редактирование и смена ветки обновляют индекс.

## Границы

Этот контракт не добавляет автоматические операции Git, общий кэш между клонами и второй MCP endpoint.
Он не задаёт длительность ожидания переподключения и внутренний алгоритм вычисления UUID.
