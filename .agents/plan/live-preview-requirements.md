# LiveNote: Live Preview и встроенные схемы

Пользователь поручил реализацию через задачи по категориям. Работать в текущем checkout, без commits и worktrees. Предыдущие изменения не откатывать.

## Критерии

1. Страница работает как Obsidian Live Preview: курсор раскрывает Markdown-маркеры только активного фрагмента, оформление сохраняется, отдельного textarea и режима редактирования всего исходника нет. Автосохранение, Cmd/Ctrl+S, undo/redo, сохранение черновика при внешнем конфликте.
2. Mermaid, BPMN и draw.io встроены среди текста. Сохранить preview, fullscreen, редактирование, export и копирование. Это главная функция приложения. Курсор рядом не раскрывает XML. Создание/сохранение вставляет схему, отмена не создаёт файлы. Можно встроить существующий файл.
3. Правый клик по документу: HeroUI Dropdown «Вставить диаграмму» → Mermaid/BPMN/draw.io. Позиция клика задаёт вставку, пустое место снизу — конец. Отдельное меню действий схемы. Сохранить текстовые clipboard actions; альтернативная кнопка для клавиатуры/телефона.
4. Справа нет постоянной панели свойств. Слева дерево/поиск/теги, сверху вкладки/история, основная площадь — документ. Название редактируется на месте, теги вводятся как #тег, backlinks сворачиваются внизу. Import/export/settings в меню, удаление/rename/move в файловом контекстном меню.
5. Иконки @gravity-ui/icons для упрощения интерфейса. HeroUI v3 и semantic tokens, доступные имена и tooltip для иконок.
6. Файлы имеют понятные имена без UUID. Путь определяет документ; обязательных ID/YAML/служебных block comments нет. Обычный Markdown без frontmatter должен открываться. Одноимённые файлы в разных папках допустимы. Rename/move из приложения обновляет относительные Markdown/wiki/embed links.
7. Папки, вложенные и пустые: create/rename/move/delete. Создание заметки в выбранной папке. Файлы схем доступны для выбора и открытия.
8. Адаптировать REST/MCP к path-based модели. Не создавать параллельную копию NoteService. Явный безопасный перенос старого vault и SQLite на копии, без изменения исходника/рабочих данных.
9. Vim mode default off, persistent setting, Normal/Insert/Visual indicator. Совместим с Live Preview, toggle сохраняет текст/selection/history. Визуальные редакторы схем сохраняют своё управление.
10. Сначала рабочий сценарий редактор+диаграмма+Vim для выбора движка. CodeMirror6 пока кандидат; стандартный IDE/demo интерфейс не брать.
11. Проверки: targeted tests, server/web types, build; реальные HTTP/browser сценарии каждой функции; desktop/mobile light/dark screenshots. Проверить упакованный CLI/глобальную установку в изолированном prefix. Не изменять реальную глобальную установку. Полный набор тестов — только по отдельному одобрению.

## Разделение

Оркестратор читает и проверяет, production edits выполняют category tasks. Контракт пишет архитектурная задача перед backend/UI интеграцией. Задача зависимостей единственная меняет package.json/package-lock.json. Новые файлы до 600 строк. Комментарии и интерфейс по-русски.

## Приёмка

Зелёные тесты не заменяют ручной сценарий написания заметки и вставки/редактирования каждого формата схемы на странице. Миграцию проверять только на собственных fixtures. Записать доказательства и очистить собственные серверы, браузеры и временные каталоги.

## Уточнения по скриншотам пользователя

- Убрать толстые рамки фокуса у редактора, названия, поиска, папок, вкладок и кнопок. Для клавиатурного фокуса использовать спокойное состояние без жирной обводки.
- Исправить слипание строк дерева и элементов управления. Центрировать три точки, убрать отдельную тяжёлую подложку. Размеры однотипных иконок должны совпадать.
- Удалить отдельное поле добавления тегов и строку тегов возле документа. Пользователь пишет `#sometag` в любом месте Markdown; фильтр тегов слева остаётся.
- Оставить в заголовке дерева один плюс с dropdown «Папка / Файл». Создавать объект сразу с понятным свободным именем и начинать переименование на месте. Модалка и поле пути для создания не нужны.
- Правый клик по папке: «Создать → Папка / Файл», «Переименовать», «Удалить». Новый объект создаётся внутри папки. При клике по файлу новый объект создаётся рядом с ним. Переименование выполняется на месте.
- Добавить drag-and-drop для перемещения файлов и папок через существующие безопасные операции vault. Поддержать перенос в корень; запретить перенос папки внутрь себя или потомка.
- Вкладки занимают ширину содержимого и не растягиваются на всю строку.
- У каждой встроенной диаграммы должна быть кнопка удаления и пункт удаления в контекстном меню. Удаление убирает встраивание из Markdown; общий внешний файл схемы сохраняется.
